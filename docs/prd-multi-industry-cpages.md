# PRD：多业态可配置 C 端页面（页面引擎 v1）

> 文档性质：产品需求规格（Feature Spec / PRD）
> 配套文档：[SAAS 化改造计划](./saas-transformation-plan.md)
> 适用范围：Phase 1 — 业态模板 + C 端页面引擎
> 遵循结构：问题 / 目标 / 非目标 / 用户故事 / 需求(P0-P2) / 指标 / 待解决 / 时间

---

## 1. 问题陈述（Problem Statement）

当前 C 端小程序页面是为"青囊中医馆"单一业态硬编码实现的。品牌名、业务术语、首屏区块组合全部写死在代码里，例如：

- `miniprogram/pages/home/home.wxml` 第 13 行写死「中医馆」、第 29-33 行写死「选择服务 / 选择技师 / 选择时段」、第 77 行写死「青囊中医馆 / 疗愈体验」；
- 首页区块固定为「服务项目 / 健康资讯」，无法按商户业务开关；
- `packages/admin-shared/src/constants.js` 第 1-14 行导航标签写死「技师管理 / 技师排班 / 技师工作台 / 提成结算」，无术语抽象。

**谁受影响、频率**：每接入一个新商户 / 新业态（如健身房），工程都要改代码、重新发版；平台方每接一单都是一次"定制项目"。

**不解决的代价**：工程无法规模化，每新增业态边际成本不降反升，直接违背"SAAS 化"的产品定位；商户无法自助调整品牌与页面，交付体验差、运维成本高。

## 2. 目标（Goals）

| # | 目标 | 类型 | 如何算成功 |
|---|------|------|-----------|
| G1 | 新增一个业态的 C 端页面可通过配置完成，无需改小程序代码 | 业务 | 健身房业态 0 代码改动上线 |
| G2 | 商户可在管理端配置品牌名、主色、首屏区块组合与文案 | 用户 | 商户自助完成品牌配置，C 端即时生效 |
| G3 | C 端业务术语随业态变化（技师 ↔ 教练，预约 ↔ 约课） | 用户 | 进入健身房租户看不到任何"中医/技师"字样 |
| G4 | 消除 C 端业务词硬编码，页面区块由配置驱动 | 技术 | 全量扫描硬编码业务词 = 0 |

## 3. 非目标（Non-Goals）

1. **不做完全自由的拖拽画布**：本期只做"模板预置区块 + 商户开关/排序/文案微调"，自由画布列为 P2。理由：控制维护成本，保证各业态体验一致性。
2. **不做计费与用量计量**：SaaS 仅以"套餐 / 能力包"门控菜单与能力，不接入支付、账单、用量统计（用户已明确不需要）。套餐门控属 Phase 3，不在本期 PRD 交付，但架构需预留 `plan → menu/capability` 映射。
3. **不做真实微信登录 + 租户隔离改造**：属 Phase 0 前置依赖，工程上先于本期，但不由本 PRD 交付。
4. **不做管理端（pc-admin / 小程序内嵌）模板化**：属 Phase 2，本 PRD 聚焦 C 端展示。
5. **不重构预约 / 排班核心模型为通用"可预约资源"**：本期对健身房先以"服务模型扩展"承载（私教≈服务），通用资源抽象留 P2。

## 4. 用户故事（User Stories）

**平台运营**
- 作为平台运营，我希望定义一套"健身房"业态模板（模块清单 + 术语 + 默认区块），以便新商户选模板即获得匹配的页面与用语。
- 作为平台运营，我希望内置模板可版本化管理，以便模板升级不影响存量租户。

**商户管理员**
- 作为商户管理员，我希望在管理端修改品牌名、主色、首页区块组合，以便我的小程序呈现自有品牌而非"中医馆"。
- 作为商户管理员，我希望开启 / 关闭某些区块（隐藏"健康资讯"、显示"团课"），以便页面契合我的业务。
- 作为商户管理员，我希望调整区块排序与文案，以便首屏突出我最想卖的内容。
- 边界：未配置时回退到业态模板默认值；错误配置（如区块数据为空）时区块优雅隐藏而非报错。

**C 端顾客**
- 作为顾客，我进入健身房租户看到「教练 / 约课 / 会员卡」而非「技师 / 预约 / 健康档案」，以便我理解并下单。
- 作为顾客，我看到的页面首屏区块顺序随该商户配置变化，且弱网 / 配置缺失时有兜底内容。
- 作为顾客（中医馆老租户），我升级后页面体验不回退，术语与区块与升级前一致。

## 5. 需求（Requirements）

### P0 — Must Have（核心，不可砍）

**R1 租户页面上下文**
- C 端所有页面请求携带并解析 `tenant_id`，页面渲染基于该租户的 `industry_template` + `page_config`。
- 验收：A 租户配置不影响 B 租户；缺失配置时回退模板默认。

**R2 业态模板（industry_templates）**
- 系统内置至少两套模板：`tcm_clinic`（中医馆，含现有全量模块）、`gym`（健身房，含教练/课程/会员卡/团课区块）。
- 模板定义：`modules`（可用模块清单）、`terms`（术语映射）、`default_sections`（默认首页区块组合）。
- 验收：新建租户选 `gym` 即获得健身房默认页面与术语，无需任何代码改动。

**R3 术语抽象层（Term Dictionary）**
- 所有 C 端面向用户的业务词（品牌名、技师/教练、预约/约课、健康档案/体测、提成/课时费等）从术语字典读取渲染，代码零硬编码中文业务词。
- 验收：全量扫描 `miniprogram/**` 业务词 = 0；切换模板后页面名词同步变化。

**R4 租户级页面区块配置（tenant_page_configs）**
- 将 `homepage_configs` 从 `store_id` 升级为 `tenant_id`，并支持多 `page_key`（home / booking / profile）。
- 区块支持：开关（is_active）、排序（sort_order）、文案（title）、封面（payload.cover_url）、数据绑定（payload.source）。
- 验收：商户在管理端关掉"健康资讯"区块，C 端首页不再出现。

**R5 C 端渲染引擎**
- 小程序端按 `page_config` 的动态 section 列表渲染；遇到模板未定义的 section 优雅跳过；配置缺失回退模板默认区块。
- 验收：配置为空时页面使用模板默认区块，不白屏、不报错。

**R6 C 端配置管理入口**
- 商户可在 `pc-admin`（本期最小集：品牌名 / 主色 / 首页区块开关排序文案）编辑本租户页面配置，保存后 C 端即时生效。
- 验收：修改品牌名保存后，C 端首页 header 文案变更。

### P1 — Should Have（重要，可作快速跟进）

**R7 多 page 区块化**：预约页、个人中心等也走区块配置（不止首页）。
**R8 区块数据来源配置**：首页"团课"区块可绑定课程列表接口 / 筛选条件。
**R9 健身房数据模型最小集**：在现有 `services` 模型上扩展 `category=gym_course` 与"教练"角色，不破坏中医馆存量；支持"会员卡 / 次卡"作为特殊服务类型。

### P2 — Future（本期不做，但架构需预留）

**R10 完全自定义区块（拖拽画布）**。
**R11 通用"可预约资源"模型**：团课 / 私教 / 服务统一容量与排班语义。
**R12 区块 A/B 测试与个性化**。
**R13 套餐能力门控**：plan 决定管理端 nav 与 C 端可用模块（与 R3 术语层、Phase 2 管理端模板化协同），仅门控不计费。

## 6. 成功指标（Success Metrics）

### 领先指标（上线后数周）
| 指标 | 基线 | 成功阈值 | 拉伸目标 | 测量方式 |
|------|------|---------|---------|---------|
| 新增业态接入工时 | 1 个定制项目（月级） | ≤ 1 人日（配置+微调） | ≤ 0.5 人日 | 交付记录 |
| C 端硬编码业务词数量 | ≥ 8 处 | 0 | 0 | 代码扫描 + 评审 |
| 商户品牌配置完成率 | 不适用 | 开通后 7 天内 ≥ 60% | ≥ 80% | pc-admin 配置日志 |

### 滞后指标（上线后 1-2 季度）
- 新租户接入边际成本下降曲线；
- C 端转化率不因改版下降（对比中医馆存量基线）；
- 租户数据越权访问事件 = 0。

## 8. 时间考虑（Timeline）

- **硬依赖**：Phase 0（多租户地基 + 认证隔离）必须先于本 PRD 联调就绪；否则 R1 无法验证。
- **建议拆分**：
  - **1a 模板与配置底座**：`industry_templates` + `tenant_page_configs` + 术语字典表 + 内置两套模板数据（R2/R3/R4）。
  - **1b 渲染引擎与管理端入口**：小程序端动态渲染 + pc-admin 品牌/区块配置最小集（R5/R6）。
  - **1c 健身房模板落地验证**：以健身房为第一个非中医业态跑通端到端，作为"0 代码新增业态"的验收样板（G1）。
- **验收里程碑**：1c 完成后，新增第三个业态（如美容院）应仅需"配置模板 + 商户微调"，工程侧只补模板数据、不改渲染代码。
