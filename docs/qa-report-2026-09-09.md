## 二、发现并修复的缺陷（3 个）

### BUG-1（P1·阻断主路径）：owner 创建用户必然 500
- **现象**：`POST /api/admin/users` 不带 `tenantId` 时返回 500。
- **根因（双因叠加）**：
  1. `admin.js` 中 `tenantId: z.coerce.number().optional()`——`z.coerce` 把 `undefined` 变成 `NaN` 触发 ZodError；
  2. 修复 schema 后仍 500：`memberLevel` 缺省时显式插入 `null`，违反 `users.member_level varchar(40) not null`（显式 null 不走列默认值）。
- **修复**：tenantId 改 `z.preprocess`（undefined/null/空串 → undefined）；`memberLevel` 缺省回退 `'青竹会员'`（与 schema 默认值一致）。

### BUG-2（P2·功能不可用）：商户交易接口缺参即 400
- **现象**：`GET /api/admin/merchant/transactions` 不带 `tenantId` 时 400。
- **根因**：query schema 将 `tenantId` 设为必填 coerce。
- **修复**：`tenantId` 改可选——商户管理员由 `tenantScope` 强制本租户；平台 owner 不传则查全部租户。

### BUG-3（P2·越权风险）：商户交易接口信任前端传参
- **现象**：接口直接使用 query 里的 `tenantId`，无任何 scope 覆盖——商户管理员可通过改参数查看**任意租户**的交易流水。
- **修复**：新增 `tenantScope ?? q.tenantId` 强制覆盖逻辑，商户管理员只能看本租户交易（主查询与汇总查询均已覆盖）。

### 已知历史问题（本轮回归验证通过）
- 上轮修复的 `cpages.js` 鉴权缺口（`requireAdmin` 注册在路由之后导致守卫不生效）——本轮实测：普通用户 PATCH 租户品牌 / PUT 租户套餐均被 **403** 拦截 ✅

## 五、遗留风险与建议（不阻塞上线）

1. **⚠️ 弱口令与明文密钥**：`wrangler.toml` 中 `ADMIN_LOGIN_PASSWORD=admin123`、`JWT_SECRET` 为占位符——建议改用 `wrangler secret put`（不进仓库）并换强密码。
2. **前端 chunk 偏大**：pc-admin 有 chunk >500kB，建议后续做 `manualChunks` 代码分割（性能优化项，非缺陷）。
3. **支付真实凭证未就位**：payments 走 mock 分支（无凭证守卫生效、不触真网），凭证到位后需再做一轮真实渠道联调。
4. **iOS IAP 校验为占位**：`/iospay/verify` 未接 App Store，上线前需补齐。
5. **表数口径**：文档中 31 表与实查 30 张的口径差异建议在 OVERVIEW.md 统一。
